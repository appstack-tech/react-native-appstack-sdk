# Releasing

## Public API baseline

`api/react-native-appstack-sdk.api.md` is the committed report of the package's
public TypeScript API, generated by
[API Extractor](https://api-extractor.com/) from `lib/typescript/index.d.ts`.
That is the file `"types"` in `package.json` points at, emitted from `src/` by
`bob build`, so it is exactly what apps compile against. Every change to it is
reviewed on purpose.

- **Tests (`tests.yml` → `integration-tests.yml`)** runs `npm run api:check` in
  the JavaScript package job. It fails when:
  - the built declarations no longer match the committed report, or
  - `api/api-surface.ts` stops compiling. That file calls every public export
    the way an app would, so a removed export or an incompatible signature
    fails here even when the report was regenerated along with it.
- **API change gate (`api-change-gate.yml`)** fails any PR that changes the
  report unless the PR has one of these labels:

  - `api-change`: additive only (new export, method, optional parameter or
    optional field). Existing apps keep compiling. A new `EventType` member also
    goes here, and so does a new method on `AppstackSDKInterface`: apps call
    the SDK rather than implement that interface.
  - `breaking`: something was removed or renamed, a parameter became required,
    a type was narrowed, or a return type changed. Decide the version bump for
    the release (not every breaking change needs a major) and call it out in
    `CHANGELOG.md`.

  The diff is in the gate job's summary. Adding or removing a label re-runs the
  gate by itself, without the build and integration tests.

To change the API intentionally:

```bash
npm run api:update
```

This rebuilds `lib/`, rewrites the report and type-checks `api/api-surface.ts`.
Commit the updated `api/react-native-appstack-sdk.api.md` with the code change,
cover any new export in `api/api-surface.ts` (for a breaking change, update the
calls that no longer compile), and label the PR.

What the report covers: only what `src/index.ts` exports. Private members, the
TurboModule spec in `src/NativeAppstackReactNative.ts` and the types in
`src/types.ts` that `index.ts` doesn't re-export are left out. Renaming or
changing the TurboModule spec is a native-bridge change, which the Android and
iOS integration tests cover, not this gate.
